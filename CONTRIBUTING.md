# Contributing

Useful contributions make this skill choose better actions without adding ceremony to unrelated work.

For feedback, include a sanitized prompt, the relevant project facts, the behavior you observed, and the outcome you expected. Distinguish a failure to select the skill from a failure after it was selected. Remove secrets, private records, and sensitive repository details.

Before changing instructions, identify a reproducible behavior problem. Prefer the smallest correction that addresses it. A domain example should remain an example rather than becoming a requirement for every application.

For a proposed change:

1. Update the affected instructions and any linked examples or documentation.
2. Check frontmatter, relative links, metadata paths, author credit, and the requested-work boundaries.
3. Add or refine a relevant case in [behavior checks](examples/behavior-checks.md). Exercise it in an isolated project when practical and report the actual outcome.
4. Add a concise entry under **Unreleased** in [CHANGELOG.md](CHANGELOG.md).

See [maintenance notes](docs/MAINTAINING.md) for the package contract and sources. Report checks honestly; a structural validator does not demonstrate agent behavior.
